# Spec Kit — ciąg dalszy

Nie porzucajcie procesu tylko dlatego, że kod już istnieje.

Zmiana wymagań oznacza powrót do odpowiednich etapów.

Sprawdźcie przede wszystkim:

```text
clarify
→ plan
→ checklist
→ tasks
→ analyze
→ implement
→ converge
```

Jeżeli zmiana wymaga również aktualizacji specyfikacji — zaktualizujcie ją.

To właśnie jest moment, w którym okaże się, czy Spec Kit był dla Was:

**procesem projektowym**

czy tylko:

**serią komend wykonanych przed pisaniem kodu.**
